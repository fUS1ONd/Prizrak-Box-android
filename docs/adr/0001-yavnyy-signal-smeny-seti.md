# ADR-0001. Явный сигнал смены сети вместо DNS-сигнала

Статус: принято, 2026-08-08.

## Контекст

Фича fast-switch требует немедленно дёргать форс-чек ядра при смене дефолтной
сети (WiFi↔LTE). Внутриядерный монитор дефолтного интерфейса на Android не
работает: туннель поднимается с AutoRoute=false, netlink приложению запрещён.
Единственный, кто знает о смене сети, — клиент, через ConnectivityManager.

Прототип использовал в качестве сигнала существующее уведомление о смене DNS
(`NotifyDnsChanged`): при переключении WiFi↔LTE системный DNS почти всегда
меняется, и вызов «бесплатно» оказывается в нужном месте. Но это совпадение,
а не гарантия:

- DNS может смениться без смены сети (обновление LinkProperties, приватный
  DNS, ручная настройка) — форс-чек стрелял бы впустую;
- сеть может смениться без смены DNS-списка (две сети с одинаковыми
  резолверами, например два WiFi с 8.8.8.8) — форс-чек не стрелял бы вовсе;
- DNS-путь получает вторую, неочевидную обязанность: любая будущая правка
  DNS-логики молча ломала бы восстановление VPN.

## Решение

Отдельный JNI-вызов `notifyNetworkChanged` без параметров: наблюдатель сетей
сервисного слоя (`NetworkObserveModule`) отслеживает сеть-победителя по своему
существующему приоритету транспорта и дёргает вызов только при её фактической
смене. Внизу вызов транслируется в `tunnel.ForceHealthCheckAll()` ядра.

DNS-путь не меняется и семантики не приобретает: уведомление о DNS — про DNS.

Детали поведения наблюдателя:

- первое заполнение списка сетей после регистрации callback-ов сменой не
  считается — но смена победителя во время стартовой пачки событий (пришла
  сеть приоритетнее уже увиденной) сигнал даёт; лишний залп на старте
  схлопывается дебаунсом ядра;
- пропадание всех сетей сигнала не даёт (стрелять некуда), но запоминается:
  появление сети после полного пропадания — смена.

## Последствия

- Переключение WiFi↔LTE вызывает форс-чек всегда, независимо от того,
  совпали ли DNS-списки сетей.
- Смена DNS без смены сети форс-чек не вызывает.
- Сигнал идемпотентен и дёшев: шторм событий ConnectivityManager схлопывается
  дебаунсом ядра (~1 с), поколения отменяют недоигранные гейты — клиенту не
  нужны собственные пороги и таймеры.
- Новый вызов проходит через все слои моста (Kotlin → JNI → cgo → ядро) —
  это +4 маленьких правки при ребейзе на апстрим, цена честного контракта.
