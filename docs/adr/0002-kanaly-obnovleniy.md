# ADR-0002. Два изолированных канала обновлений, сравнение по метаданным сборки

Статус: принято, 2026-08-08.

## Контекст

В приложении уже был встроенный апдейтер (`UpdateChecker`): раз в 12 часов при
старте ходил в GitHub, показывал уведомление, качал APK через `DownloadManager`
и звал системный установщик. Смотрел он при этом в `legiz-ru/Prizrak-Box` —
репозиторий апстрима, к тому же не android-клиента. То есть работал, но не на
наши релизы.

Наши сборки делятся на два флейвора с **разными applicationId**
(`ru.legiz.prizrakbox.meta` и `...alpha`) — это два разных приложения, которые
могут стоять на телефоне одновременно. Апдейтер об этом не знал: alpha-сборка
получала предложение обновиться до meta-релиза и качала APK, который поверх неё
не встанет.

Каналы устроены принципиально по-разному:

|                | meta                | alpha                          |
|----------------|---------------------|--------------------------------|
| тег            | `vX.Y.Z`, растёт    | `Prerelease-alpha`, постоянный |
| публикация     | вручную             | на каждый push в `main`        |
| имя версии     | из тега             | `1.1`, не менялось             |
| код версии     | из тега             | `101`, не менялся              |

У alpha ни тег, ни версия, ни имя файла не несут информации о свежести: релиз
каждый раз удаляется и создаётся заново с тем же именем. Сравнивать нечего.

## Решение

**Канал обновлений привязан к флейвору сборки** — через
`buildConfigField("String", "UPDATE_CHANNEL", ...)`, а не выводится из
`applicationId` или имени версии. Свойство сборки `remove.suffix` стирает и
суффикс applicationId, и суффикс имени версии, поэтому любой вывод канала из
этих строк на такой сборке разваливается молча.

**Каналы изолированы**: meta смотрит только на релизы `vX.Y.Z`, alpha — только
на плавающий пререлиз. Переезд пользователя между каналами обновлением
невозможен и не предполагается — это разные приложения.

**«Свежее ли» и «какой файл качать» решаются по метаданным сборки** —
`output-metadata.json`, который Gradle и так кладёт в каждый релиз. Из него
берутся код версии (сравнение), имя файла нужной архитектуры (вместо угадывания
имени по маске) и applicationId (проверка, что сборка вообще предназначена
нашему приложению). Один механизм на оба канала.

**Alpha получает монотонный код версии из CI**: `100000 + номер прогона`.
Смещение обязательно — голый номер прогона меньше прежнего `101`, и система
отказала бы в установке как в откате назад. Значение передаётся в сборку через
`local.properties` (единственный конфиг, который читает `build.gradle.kts`);
переписывать `build.gradle.kts` в этом workflow нельзя — он триггерится на push
в `main` и коммит из него зациклил бы сборки.

**Ченджлог alpha чинится в CI, а не в клиенте**: тело пререлиза собирается из
коммитов с прошлого пререлиза, граница берётся из тега до его удаления. Иначе
клиенту достаётся автосписок всех PR с начала репозитория — он только растёт.

## Рассмотренные альтернативы

- **Сравнивать semver из тега.** Работает для meta, для alpha неприменимо в
  принципе (тег постоянный). Дал бы два разных механизма «как определить
  свежее» в одном классе.
- **Свежесть alpha по времени публикации релиза** против времени установки
  пакета. Не требует правок CI, но врёт при любой ручной переустановке и при
  перезаливке релиза без изменений кода.
- **Свежесть alpha по SHA коммита.** Отвечает «отличается», а не «свежее» — на
  откате ветки предложил бы «обновиться» назад.
- **Полностью исключить alpha из обновлений** (исходная постановка). Отвергнуто:
  ежедневные сборки как раз и нужны тем, кто хочет свежее сразу.

## Последствия

- Alpha-сборки впервые начинают ставиться поверх друг друга как обновление:
  раньше код версии не менялся.
- Проверка обновлений стоит двух сетевых запросов вместо одного (релиз +
  метаданные сборки, ~2.5 КБ).
- Появление третьего флейвора требует явного решения о его канале — это плюс:
  умолчания здесь опаснее, чем ошибка компиляции.
- Отказ от предложения не запоминается сознательно: предложение повторяется на
  следующей проверке. Шум ограничен интервалом — 12 часов для meta, 72 для
  alpha, потому что alpha публикуется на каждый push.
